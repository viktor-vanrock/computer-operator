# ТЗ: Скачивание логов Full Duplex-сессии на техстенде

## Цель

Добавить в интерфейс Full Duplex-сессии на техстенде кнопку скачивания архива `steps.zip`, передавая файл от сервиса Full Duplex потоком без блокировки event loop и полной загрузки архива в память.

## Контекст

Техстенд — приложение `apps/frontend-tech`, экран Full Duplex-сессии находится в `apps/frontend-tech/src/features/arena/arena-full-duplex.tsx`. Его верхняя панель — общий компонент `ArenaTopBar` из `packages/ui/src/ui/arena-top-bar/`.

Бэкенд техстенда — Fastify-приложение в `apps/backend`. Оно уже подключено к сервису Full Duplex через `FULL_DUPLEX_API_URL`, `FULL_DUPLEX_USERNAME` и `FULL_DUPLEX_PASSWORD`. Учётные данные должны оставаться только на стороне бэкенда.

Endpoint сервиса Full Duplex: `GET /full_duplex/sessions/<ID>/steps.zip`, где `ID` — `sessionId` текущей сессии. Архив может иметь размер 40–50 МБ, а ответ сервиса может формироваться долго.

## Требования

### Функциональные

- [ ] Добавить на экран Full Duplex-сессии кнопку скачивания логов; во время операции блокировать повторное нажатие.
- [ ] По нажатию запрашивать архив для `sessionId` текущего экрана.
- [ ] Скачать архив браузером как файл, используя имя из `Content-Disposition`; если заголовок отсутствует, использовать имя с `sessionId`.
- [ ] Показывать подготовку/ход скачивания, процент при наличии `Content-Length`, краткое уведомление о начале сохранения с последующим возвратом исходной подписи и понятную ошибку с возможностью повтора.
- [ ] Выполнять запрос к сервису Full Duplex через бэкенд техстенда. Не обращаться к сервису напрямую из браузера и не передавать клиенту Basic Auth credentials.
- [ ] При ошибке upstream-запроса вернуть клиенту ошибочный HTTP-статус без стека-трейса и внутренних учётных данных.

### Нефункциональные

- [ ] Передавать архив потоково. Не собирать весь архив через `arrayBuffer()`, `blob()` или аналогичную буферизацию в памяти бэкенда.
- [ ] Не выполнять синхронные операции, блокирующие event loop, пока upstream формирует или передаёт архив.
- [ ] Во время загрузки интерфейс должен оставаться отзывчивым.
- [ ] При прерывании загрузки клиентом отменять upstream-запрос, если это поддерживается используемым HTTP-клиентом.

## Технические детали

Добавить Fastify-маршрут техстенда `GET /sessions/:id/steps.zip`. Маршрут должен проверить UUID, убедиться, что сессия имеет режим `FULL_DUPLEX`, и вызвать upstream endpoint с существующими серверными credentials. Ответ передавать клиенту потоком, копируя `Content-Type` и `Content-Disposition`, а при отсутствии последнего указывать имя `steps-<sessionId>.zip`.

Кнопку добавить в `ArenaTopBar` через необязательный callback. Показывать её только на Full Duplex-экране. Инициировать загрузку через `fetch` с cookie credentials, читать response body по частям, показывать прогресс и после получения архива предлагать его браузеру для сохранения. Это должно оставить страницу сессии смонтированной: её обработчики `beforeunload` и cleanup отправляют остановку сессии при уходе со страницы. Передавать `Content-Disposition` и `Content-Length` браузеру через `Access-Control-Expose-Headers`.

## Критерии приёмки

- [ ] На экране Full Duplex-сессии есть кнопка, которая использует ID открытой сессии.
- [ ] Нажатие инициирует загрузку ZIP с подходящим именем файла, не покидая экран сессии.
- [ ] Пока архив готовится и передаётся, в интерфейсе виден статус; при известном размере отображается процент.
- [ ] Бэкенд потоково передаёт ZIP и не буферизует его целиком.
- [ ] Во время долгого upstream-ответа event loop и интерфейс остаются отзывчивыми.
- [ ] Ошибочный upstream-ответ не возвращается клиенту как ZIP с HTTP 200.
- [ ] Для SOLO-режима кнопка не отображается.
- [ ] Тестами проверить успешный ответ, upstream-ошибку и неверный `sessionId`.

## Что НЕ входит в задачу

- Изменение состава или формата архива на стороне Full Duplex-сервиса.
- Просмотр логов внутри техстенда.
- Скачивание логов SOLO-сессий.
- Страница результатов или список архивов.
