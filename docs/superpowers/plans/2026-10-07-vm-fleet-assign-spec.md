# ТЗ: Назначение VM из пула через VM Fleet assign

## Цель
Выдавать сессии VM только после атомарного назначения через VM Fleet, предотвращая выдачу одной машины разным клиентам.

## Контекст
Backend использует `VMFleetClient.reserveAvailable()` для Preset OS и Custom OS Image в SOLO и FULL_DUPLEX. Сейчас клиент выбирает VM из списка и отмечает её в локальном Set; сервис дополнительно связывает её с сессией через SQL claim и частичный уникальный индекс `Session_active_vmName_key`.

## Требования

### Функциональные
- [ ] Получать кандидатов через `GET /api/v1/vms?profile=reserved_vm&state=READY&assigned=false&image=<image>`.
- [ ] Сохранять исключения по имени, проверку готовности и наличия данных подключения.
- [ ] До возврата VM вызвать `POST /api/v1/vms/{id}/assign` без тела, с Bearer-токеном и UUID `Idempotency-Key`; кодировать ID в пути.
- [ ] При `200` проверить объект VM, соответствие ID и имени кандидату, `status=assigned` и данные подключения. Вернуть данные из ответа assign.
- [ ] При `409 already_assigned`, `409 invalid_state` или `404` перейти к следующему кандидату из полученного списка; каждую VM пробовать не более одного раза, кроме ограниченных повторов HTTP-запроса.
- [ ] При исчерпании списка вернуть существующую ошибку отсутствия доступной VM; сохранить перевод сессии в FAILED с причиной `VM_RESERVATION_EXHAUSTED`.
- [ ] Остальные постоянные ошибки не скрывать переходом к другой VM.
- [ ] Ставить локальную блокировку кандидата до POST; снимать её при неуспешном назначении. Сохранить SQL claim и уникальный индекс.
- [ ] После подтверждённого назначения удалять VM существующим механизмом при некорректном ответе assign или ошибке сохранения связи с сессией. При конфликте уникальности (P2002 / SQLSTATE 23505) или отсутствии результата SQL claim проверить наличие активной сессии с этим vmName: если владельца нет — запустить удаление; если есть — сохранить используемую машину. Затем исключить кандидата и перейти к следующему. Если проверка владельца завершается ошибкой, прекратить запуск без удаления VM с неопределённым владельцем.
- [ ] Сохранить удаление VM по завершении сессии; `releaseReservation()` снимает только локальную отметку и не отменяет assign.

### Нефункциональные
- [ ] Сохранить таймаут 30 секунд и существующие ограниченные повторы временных HTTP-ошибок и таймаутов, используя один ключ для всех повторов одного назначения.
- [ ] После исчерпания повторов с неопределённым результатом завершать запуск ошибкой, не назначая другую машину.
- [ ] Не раскрывать Bearer-токен в логах и ошибках.
- [ ] Проверить гонки внутри одного клиента и между независимыми клиентами, конфликты, повторы, актуальные данные подключения и очистку.

## Технические детали
TypeScript, Node.js fetch, Prisma/PostgreSQL, Vitest. Новые зависимости и миграции не требуются. VM Fleet требует право `fleet:create` и не хранит клиентскую сессию. Допущение по предоставленному OpenAPI: `IdempotencyKey` обеспечивает повтор результата одной операции при повторе с тем же ключом. `ReservedVm.status` продолжает отображать `actual_state`; поле `status=assigned` используется для проверки ответа Fleet.

## Критерии приёмки
- [ ] VM возвращается только после HTTP 200 с корректным объектом назначенной машины.
- [ ] Конфликт первого кандидата позволяет выдать второго; назначенная VM без активного владельца удаляется, а VM активной сессии сохраняется.
- [ ] Независимые клиенты с одним исходным списком получают разные VM при атомарном поведении assign.
- [ ] Все повторы одного POST передают одинаковый ключ, разные назначения — разные ключи.
- [ ] Ошибки авторизации и неизвестные конфликты останавливают запуск.
- [ ] Тесты backend, typecheck, сборка и ESLint изменённых TypeScript-файлов проходят.

## Что НЕ входит в задачу
- Изменения самого VM Fleet, размера пула, max_vms или прав токена в инфраструктуре.
- Создание новых VM через deployments, новая ручка выдачи в Computer Operator или изменения UI.
- Отмена назначения отдельной ручкой, изменение схемы БД или существующего удаления VM.

## Примеры / Референсы
Контракт предоставлен пользователем: `POST /api/v1/vms/{id}/assign`, `200` с объектом VM и `status=assigned`, `404`, `409 already_assigned` и `409 invalid_state`. Назначенная VM исключается из списка `state=READY&assigned=false`; пул заказывает замену, а клиент удаляет VM после использования.

Пример гонки: список содержит A и B; assign(A) возвращает `409 already_assigned`; assign(B) возвращает `200`; сессия получает только B.
