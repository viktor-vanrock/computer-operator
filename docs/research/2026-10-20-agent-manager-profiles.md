# Выбор профиля Agent Manager на техническом стенде

Для SOLO и HUMAN_VS_AGENT технический стенд загружает каталог через `GET /sessions/profiles`.
Backend обращается к `GET /profiles` Agent Manager с существующей серверной авторизацией.
Исходный объект `{ "<key>": { "display_name": "<label>" } }` преобразуется в
`{ "data": [{ "id": "<key>", "displayName": "<label>" }] }`.
Дополнительные настройки профиля клиенту не передаются.

Техстенд показывает `displayName` и отправляет исходный ключ в `POST /sessions.agentLeftModel`.
Backend проверяет явно выбранный профиль по актуальному каталогу. Отсутствующий ключ возвращает
`MODEL_NOT_SUPPORTED`, ошибка загрузки каталога — `BAD_GATEWAY`. Каталог не зашит в коде.
Пустой каталог, загрузка и ошибка запрещают запуск из формы; ошибка позволяет повторить запрос.
Смена каталога не заменяет явно выбранную модель автоматически.

В `OPEN_SESSION` ключ передаётся **на верхнем уровне**:

```json
{
  "type": "OPEN_SESSION",
  "profile": "Qwen3.8-27B",
  "config_override": {
    "max_iterations": 25,
    "model_retries": 4,
    "actuator": { "config": { "mouse_click_delay": 0.1, "min_operation_delay": 2 } }
  }
}
```

Поле `profile` внутри `config_override` не передаётся. В примере опущены параметры VM/Guacamole.
Выбор хранится в Session; для арены сохраняются также ключ и подпись в SessionRace.
Перезапуск сохраняет профиль, а повтор создания по тому же Idempotency-Key сохраняет первоначальный запрос.

Демо продолжает передавать `computer-operator`. Старые декоративные идентификаторы моделей,
которых нет в каталоге, используют прежний профиль `default`; реальные одноимённые ключи каталога
имеют приоритет. Отсутствующее поле выбора также использует `default`.
Full Duplex сохраняет прежний протокол и не запрашивает каталог моделей в интерфейсе.

## Проверка 20 октября 2026

Живой `/profiles` вернул:

| Ключ | display_name |
| --- | --- |
| default | Computer Operator |
| Qwen3.8-27B | Qwen 3.8-27B |

`Qwen3.6-35B-A3B` в этом каталоге отсутствует: интерфейс его не добавляет самостоятельно,
а явный запрос создания с таким ключом отклоняется с `MODEL_NOT_SUPPORTED`.

В локальном backend с настоящими Agent Manager, Guacamole и VM Fleet проверены:

- SOLO с `Qwen3.8-27B`: получен STEP INCOMPLETE с текстом и действием двойного клика.
- SOLO с `default`: получены STEP INCOMPLETE, model_response и действия клика.
- HUMAN_VS_AGENT с `Qwen3.8-27B`: оба рабочих стола готовы, получены RACE_ACTION
  с мыслями и действиями; подпись агента — `Qwen 3.8-27B`.

Это проверка старта и выполнения первых шагов, без оценки качества выполнения задания.
Все три тестовые сессии остановлены; активных VM claims для них осталось 0,
очистка соревнования имеет статус COMPLETE.
Для показа локального SPA в браузере подменялся только `GET /auth/me`; API сессий,
каталог, WebSocket, Guacamole и Agent Manager использовались настоящие.

Автоматические проверки покрывают верхнеуровневое поле profile, чтение реального HTTP-клиента
с локальным сервером профилей, минимальный DTO, ошибки/пустой каталог, совместимость старых ID,
передачу выбора из обеих форм, сохранение выбора при повторе запроса, запуск race и
сохранение ключа/подписи в изолированной PostgreSQL-базе.
